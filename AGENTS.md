# Сопровождение Statistika

## Источник и проверка

- Оригиналы в `main` на коммите `65b1b032531a45fa91ede4b0accd36d1abc50f7b`: `4-торг инст..pdf` и `Ведомость 16.11.2026 (ОК).xlsx`. Временно выгружайте через `git fetch origin main` и `git show <sha>:<имя файла>`, не переключая рабочую ветку и не добавляя оригиналы или отчёты в коммиты.
- Исходный PDF — Белстат от 19.06.2026 №33, 17 страниц. `statistika/data/catalog.json` хранит результат `parse_points(extract_pdf_text(path)[0])`: пункты №1–74, включая продолжения на следующей странице. Номера назначаемых пунктов не равны номерам строк формы. №100 добавлен приложением. При правках не перезаписывайте `points` словарём классификации.
- Реальная ведомость: `Лист_1`, заголовок в строке 7, 33 224 товарные строки. Период 01.11.2023–15.11.2026. `A` — склад, `B` **не используется**, `E` — товар, `F` — единица, `I` — расход, `J` — количество конечного остатка, `N` — розничная цена, `Q:BA` — 37 месяцев. В 11 937 строках сумма по месяцам не равна `I`. Не считайте расход реализацией подпериода. Фактической суммы продаж нет. По п. 16 запасы считаются в розничных ценах; три ненулевых остатка без одной числовой цены оставьте без суммы.
- Проверка оригинала: 33 224 строки во всех режимах, два склада (Мир 19 948, Кореличи 13 276); `0206051` в строках 254 и 20132 получает №53. При экспорте обоих складов и отдельного склада проверяйте шесть детальных столбцов, строку «Без группы», сводку по единицам, дату снимка и неполный ноябрь. При раннем конце диапазона остатки должны быть пустыми. Храните тестовые данные небольшими и синтетическими.

## Модули

| Файл | Контракт |
|---|---|
| `statistika/catalog.py`, `statistika/data/catalog.json` | Точный текст инструкции, разрешённые группы, исходные и локальные фразы. Исходные правила 4-торг используются по совпадению текста пункта. Для другого текста доступны простые термины описания, видимые в редакторе. |
| `statistika/classifier.py` | Матчит только названия по эффективным спискам фраз всех групп. Нормализует регистр, `ё`, окончания, `д/`, фасовки и проценты, поддерживает `^`, `!`, ` + ` и `#`. После исключений нужен ровно один кандидат. Нет отдельного набора скрытых правил. См. `docs/recognition.md` для проверки конкретных товаров и синтаксиса. |
| `statistika/statement.py` | XLSX/XLSM/XLS/CSV/TSV, общее сопоставление пяти полей. Индексы столбцов с 0, номера строк с 1. Метрики — `Decimal` или `None`; `Product` хранит склад и единицу. |
| `statistika/warehouse.py` | Профиль ТМЦ по заголовкам без требования B. `SalesQuantity.MONTHS` принимает `(first, last)` — индексы месяцев с 0, включительно; `OUTFLOW` — только весь период. `ReportPeriod` и `column_notes` фиксируют метод, месяцы и дату запасов. Не брать снимок запасов для раннего конца периода. |
| `statistika/report.py` | Автоназначение по имени; ручные правки и очистка переживают пересчёт. Итоги по группам, единицам и выбранному складу, пропуски не нули. Экспорт: ровно 6 детальных колонок в исходном порядке и отдельный лист «Сводка по группам». Скрытие назначенных/неназначенных строк не влияет на экспорт. |
| `statistika/dialogs.py`, `statistika/app.py`, `statistika/inline_picker.py` | Tkinter: импорт, редактирование всех списков, выбор склада, сводка, выпадающий список над или под первой ячейкой (не диалог). `python -m statistika`. |
| `tests/` | `python -m pytest -q` без GUI. В workflow отдельно запускается `Statistika.exe --self-test RESULT_FILE` для проверки Tk, редактирования фраз, выбора в ячейке, импорта с месяцами, склада и экспорта. |

Локальный справочник Windows: `%LOCALAPPDATA%\Statistika\catalog.json`. JSON v2: `{ "version": 2, "source": "имя.pdf", "points": { "53": "точный текст" }, "rules": { "53": ["^антисептик", "!для рук"] } }`. Отсутствующий ключ `rules[группа]` оставляет исходный список; явный `[]` отключает автоматическое распознавание этой группы. v1 читается с объединением старых пользовательских и исходных фраз; при сохранении пишется v2. Прежде чем менять фразы, проверяйте совпадения на положительных и соседних отрицательных названиях. Не заявляйте, что автомат проверил назначение каждого товара.

## Автосборка и выпуск

`.github/workflows/windows.yml` запускается при `push` на рабочую ветку. Обычный коммит собирает и выкладывает проверенный артефакт `Statistika-Windows-x64` (30 дней). В Windows-джобе разрешено чтение; права записи только у отдельной джобы публикации.

Для следующего релиза подготовьте `docs/releases/vX.Y.Z.md`, выполните тесты и отправьте коммит с темой **`Release vX.Y.Z`** в текущую ветку. После Windows-теста джоба `release` скачивает проверенный артефакт и вызывает `gh release create` с текущим SHA и `Statistika.exe` в Assets. Не переиспользуйте номер версии и не коммитьте EXE. Для обычного коммита не используйте релизную тему. `workflow_dispatch` доступен после появления workflow в ветке по умолчанию.
