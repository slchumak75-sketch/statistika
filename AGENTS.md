# Сопровождение Statistika

## Источник и проверка

- Исходники обнаружены в `main` на коммите `65b1b032531a45fa91ede4b0accd36d1abc50f7b`: `4-торг инст..pdf` и `Ведомость 16.11.2026 (ОК).xlsx`. Их можно прочитать через `git fetch origin main` и `git show <sha>:<имя файла>` в локальный временный каталог, не переключая рабочую ветку. Не дублируйте исходную ведомость в коде, тестах или релизе.
- PDF — указания Белстата от 19.06.2026 № 33, 17 страниц. `statistika/data/catalog.json` содержит результат `parse_points(extract_pdf_text(path)[0])`: пункты №1–74 с исходными формулировками, включая продолжения на следующей странице и исключения. Разрешённые номера — пункты, а не строки статистической формы. №100 добавлен приложением.
- Реальная ведомость: `Лист_1`, строка 7 — заголовок, строки 8–33231 — 33 224 позиции двух складов. Период 01.11.2023–15.11.2026. `B` — подгруппа номенклатуры; `E` — товар; `I` — расход; `J` — количество конечного остатка; `N` — розничная цена; `Q:BA` — месяцы. `I` и сумма месяцев различаются в 11 937 строках; не считайте один из этих показателей продажами без подтверждения пользователя. Суммы фактических продаж нет. По п. 16 стоимость остатка считаем по розничной цене. Для трёх ненулевых остатков нет одной пригодной цены, сумма остаётся пустой.
- Проверен импорт полного файла в каждом режиме источника количества и экспорт XLSX: **33 224 строки данных × 6 столбцов**. Правила назначают группы на основе наименования, а не сертифицируют каждый товар. Тесты используют небольшие синтетические книги и характерные названия без рабочих оборотов.

## Модули

| Файл | Контракт |
|---|---|
| `statistika/catalog.py`, `statistika/data/catalog.json` | Парсер PDF/редактора, все точки документа в JSON v1, штатные и локальные данные. Правила 4-торг включаются только для пунктов с совпадающим проверенным текстом. Пустая конфигурация прототипа не скрывает встроенные пункты, непустая пользовательская сохраняется. |
| `statistika/rules_4_torg.py`, `statistika/classifier.py` | Предметные правила и исключения для проверенного PDF, №100, пользовательские фразы и простые совпадения для другого справочника. Контекст строительной группы сам по себе недостаточен (например, «2 Обои» содержит и корм). Несколько разных совпадений дают `None`. При изменении правила добавляйте положительные и близкие отрицательные тесты. |
| `statistika/statement.py` | Чтение XLSX/XLSM/XLS/CSV/TSV, общее сопоставление пяти полей. Индексы столбцов с 0, строки заголовка с 1. Значения — `Decimal` или `None`, порядок источника сохраняется. |
| `statistika/warehouse.py` | Отдельный профиль ТМЦ по заголовкам, а не имени файла. Количество продаж выбирается пользователем; сумма не подменяется оценкой. `ImportedProducts.summary` и `column_notes` сохраняют метод расчёта. Для выбора источника многозначная цена в одной ячейке не разрешается автоматически. |
| `statistika/report.py` | Ручное назначение, в т. ч. очистка, переживает пересчёт. Экспорт всегда в шесть столбцов и со всеми строками. Полное описание из PDF — текст, показатели — числа, пропуски — пустые ячейки. При импорте ТМЦ к заголовкам записываются пояснения. |
| `statistika/dialogs.py`, `statistika/app.py` | Tkinter: предварительная проверка, профиль ТМЦ или обычный импорт, справочник, ручной выбор, фильтрация только для отображения. Вход: `python -m statistika`. |
| `tests/` | `python -m pytest -q` без дисплея или Tk. В штатном workflow отдельный `Statistika.exe --self-test RESULT_FILE` проверяет GUI, обычный импорт, профиль ТМЦ и экспорт собранного файла. |

JSON справочника: `{ "version": 1, "source": "имя.pdf", "points": { "35": "точный текст" }, "rules": { "35": ["характерная фраза"] } }`. На Windows локальный файл в `%LOCALAPPDATA%\Statistika\catalog.json`. Перед обновлением встроенного ресурса сверьте точный PDF, его нумерацию и исключения; не переносите правила автоматически на изменённые пункты.

## Автосборка и выпуск

`.github/workflows/windows.yml` запускается при `push` на рабочую ветку. Обычный коммит собирает, проверяет и выкладывает артефакт `Statistika-Windows-x64` на 30 дней. В Windows-джобе разрешено только чтение репозитория; права записи получает отдельная джоба публикации.

Чтобы выпустить следующую версию, подготовьте `docs/releases/vX.Y.Z.md`, выполните тесты и отправьте коммит с темой **`Release vX.Y.Z`** в текущую ветку. После успешного Windows-теста джоба `release` скачивает именно проверенный артефакт и вызывает `gh release create` с текущим SHA и `Statistika.exe` в Assets. Не используйте уже опубликованный номер версии и не коммитьте EXE. Для обычных изменений не используйте релизную тему. Ручной `workflow_dispatch` для обычной сборки доступен после появления workflow в ветке по умолчанию.
