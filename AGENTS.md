# Сопровождение Statistika

## Источник и проверка

- Оригиналы в `main` на коммите `65b1b032531a45fa91ede4b0accd36d1abc50f7b`: `4-торг инст..pdf` и `Ведомость 16.11.2026 (ОК).xlsx`. Временно выгружайте через `git fetch origin main` и `git show <sha>:<имя файла>`, не переключая рабочую ветку и не добавляя оригиналы или отчёты в коммиты.
- Исходный PDF — Белстат от 19.06.2026 №33, 17 страниц. `statistika/data/catalog.json` хранит результат `parse_points(extract_pdf_text(path)[0])`: пункты №1–74, включая продолжения на следующей странице. Номера назначаемых пунктов не равны номерам строк формы. №100 добавлен приложением. При правках не перезаписывайте `points` словарём классификации.
- Реальная ведомость: `Лист_1`, заголовок в строке 7, 33 224 товарные строки. Период 01.11.2023–15.11.2026. `A` — склад, `B` **не используется**, `E` — товар, `F` — единица, `I` — расход, `J` — количество конечного остатка, `N` — розничная цена, `Q:BA` — 37 месяцев. В 11 937 строках сумма по месяцам не равна `I`. Не считайте расход реализацией подпериода. Столбец D — количество выбранного периода × розничная цена, а не фактическая выручка. По п. 16 запасы считаются в розничных ценах. При ненулевом количестве без одной числовой цены оставляйте сумму пустой независимо от показателя; нулевое количество даёт ноль.
- Проверка оригинала: 33 224 строки во всех режимах, два склада (Мир 19 948, Кореличи 13 276); `0206051` в строках 254 и 20132 получает №53. При экспорте обоих складов и отдельного склада проверяйте шесть детальных столбцов, строку «Без группы», сводку с суммой всех единиц без пересчёта, дату снимка и неполный ноябрь. При раннем конце диапазона остатки должны быть пустыми. Храните тестовые данные небольшими и синтетическими.

## Модули

| Файл | Контракт |
|---|---|
| `statistika/catalog.py`, `statistika/data/catalog.json` | Точный текст инструкции, разрешённые группы, исходные и локальные фразы. Исходные правила 4-торг используются по совпадению текста пункта. Для другого текста доступны простые термины описания, видимые в редакторе. |
| `statistika/classifier.py` | Матчит только названия по эффективным спискам фраз всех групп. Нормализует регистр, `ё`, окончания, `д/`, фасовки и проценты, учитывает позицию, исключения и уточнения из отдельных полей правила. У №53 один список распознавания, в том числе для уверенно распознанных монтажных товаров. После исключений нужен ровно один кандидат. Нет отдельного набора скрытых правил. См. `docs/recognition.md` для проверки конкретных товаров и границ №53. |
| `statistika/statement.py` | XLSX/XLSM/XLS/CSV/TSV, общее сопоставление пяти полей. Индексы столбцов с 0, номера строк с 1. Метрики — `Decimal` или `None`; `Product` хранит склад и единицу. |
| `statistika/warehouse.py` | Профиль ТМЦ по заголовкам без требования B. `SalesQuantity.MONTHS` принимает `(first, last)` — индексы месяцев с 0, включительно; `OUTFLOW` — только весь период. `ReportPeriod` и `column_notes` фиксируют расчёт по розничной цене, месяцы и дату запасов. Не брать снимок запасов для раннего конца периода. |
| `statistika/report.py` | Автоназначение по имени; ручные правки и очистка переживают пересчёт. Объём тары переопределяется для отдельной строки. Для №35–43 и №45 «Продано дал.» и «Остаток дал.» равны соответствующему количеству × объёму в литрах **без деления на 10**; при пропуске любого множителя значение пустое. Эти три колонки — только в таблице товаров. В сводке все известные количества складываются без деления по единицам, пропуски не нули. Экспорт: ровно 6 детальных колонок в исходном порядке и отдельный лист «Сводка по группам». Фильтр группы не влияет на сводку и экспорт. |
| `statistika/volume.py` | Автоподстановка одного однозначного объёма из названия (`л`/`мл`); округление и вывод из числа без единицы в названии не требуются. Ручной ввод — положительное число, запятая или точка, без единицы считается литрами. Пустой ввод снимает правку. В исходной ведомости для 465 из 487 строк целевых групп найден объём, у остальных требуется ручной ввод. |
| `statistika/dialogs.py`, `statistika/app.py`, `statistika/rule_editor.py`, `statistika/inline_picker.py`, `statistika/inline_entry.py` | Tkinter: прямой импорт распознанных листов; ручной выбор столбцов только при неясном заголовке, без предпросмотра. Период меняется из закешированного листа без сброса склада, фильтра, ручных групп или объёмов; сами правки таблицы не хранятся между запусками. Справочник: вкладки Пункты PDF и Правила распознавания; один выбор группы с описанием, поиск, добавление, флажки, Исключение/Удалить. В таблице товаров: фильтр групп в шапке, выбор группы у ячейки, двойной щелчок для выделения фрагмента названия или ввода объёма. `python -m statistika`. |
| `tests/` | `python -m pytest -q` без GUI. `Statistika.exe --self-test RESULT_FILE` проверяет Tk: вкладки и редактирование справочника, импорт, выбор и фильтр группы, расчёты при смене периода, Excel, выделение/копирование части имени и ручной объём. При повторном открытии из профиля подхватывается справочник, но не правки таблицы. |

Локальный справочник Windows: `%LOCALAPPDATA%\Statistika\catalog.json`. JSON v3: `{ "version": 3, "source": "имя.pdf", "points": { "53": "точный текст" }, "rules": { "53": [{"phrase":"антисептик","at_start":true},{"phrase":"для рук","exclude":true}] } }`. `also` и `also_at_start` хранят обязательные дополнительные фразы; `disabled: true` оставляет фразу в редакторе, но исключает её из распознавания. Устаревший `internal_only` игнорируется при чтении и не сохраняется. Тексты редактируются только на вкладке Пункты PDF; переключение `exclude` и `disabled` не меняет других условий фразы. Отсутствующий ключ `rules[группа]` оставляет исходный список; явный `[]` отключает автоматическое распознавание этой группы. v1 дополняет встроенный список, v2 заменяет его. Старые служебные знаки переносятся в поля, при сохранении пишется v3. Только точная копия неизменённого старого №53 в v2 обновляется до текущего исходного набора. Изменения и явные пустые списки сохраняются. Прежде чем менять фразы, проверяйте совпадения на положительных и соседних отрицательных названиях. Не заявляйте, что автомат проверил назначение каждого товара.

## Автосборка и выпуск

`.github/workflows/windows.yml` запускается при `push` на рабочую ветку. Обычный коммит собирает и выкладывает проверенный артефакт `Statistika-Windows-x64` (30 дней). В Windows-джобе разрешено чтение; права записи только у отдельной джобы публикации.

Для следующего релиза подготовьте `docs/releases/vX.Y.Z.md`, выполните тесты и отправьте коммит с темой **`Release vX.Y.Z`** в текущую ветку. После Windows-теста джоба `release` скачивает проверенный артефакт и вызывает `gh release create` с текущим SHA и `Statistika.exe` в Assets. Не переиспользуйте номер версии и не коммитьте EXE. Для обычного коммита не используйте релизную тему. `workflow_dispatch` доступен после появления workflow в ветке по умолчанию.
