# Сопровождение Statistika

## Текущее состояние

- Базовый `f20f907d55b9a707c4ab9889012d8f7dfa522486` и дерево `main` на момент реализации содержали только `README.md`. Образцов PDF и ведомости не было. Программа рассчитана на импорт пользователем; только для №100 имеется встроенное подтверждённое наименование. Тестовые тексты не являются описаниями из исходного документа.
- Цель — настольная сборка Windows x64. Никакой учётной записи, API, БД или внешнего сервера при использовании не нужно. Не добавляйте рабочие ведомости в репозиторий: они могут содержать конфиденциальные данные.

## Где что менять

| Файл | Контракт |
|---|---|
| `statistika/catalog.py` | Список назначаемых групп, PDF с текстовым слоем, редакторный формат `номер. текст`, JSON v1 и путь локального справочника. Сохраняются все распознанные целочисленные пункты; подпункты остаются внутри родительского описания. №100 приложения не заменяет одноимённый номер исходного PDF в `points`. |
| `statistika/data/catalog.json` | Заводской ресурс PyInstaller. Реальные пункты вносить только после сверки с PDF. Уже сохранённый локальный файл имеет приоритет над заводским. |
| `statistika/classifier.py` | Словарь №100, сопоставление фраз со стеммингом; несколько совпавших групп дают `None`. Добавления лучше проверять на близких товарах, которые НЕ входят в группу. |
| `statistika/statement.py` | Чтение листов, эвристика одно- и многострочных заголовков, проверка пяти полей, перевод в `Decimal`. `ImportPlan` хранит строки заголовка с 1, индексы колонок с 0. Никаких агрегатов или пересчёта остатков. |
| `statistika/report.py` | Модель отчёта: ручное назначение (включая явное очищение) переживает пересчёт. Экспорт во все шесть столбцов независимо от фильтра, числа пишутся числами Excel. |
| `statistika/dialogs.py`, `statistika/app.py` | Tkinter: проверка импорта, редактор справочника и правил, выбор группы в первом столбце, таблица и экспорт. Вход — `python -m statistika`. |
| `tests/` | Тесты на синтетических данных; создают временные PDF, XLSX, XLS, CSV/TSV. Можно запускать `python -m pytest -q` без дисплея/Tk. |
| `.github/workflows/windows.yml` | `push` запускает Windows-раннер с Python 3.12, тесты, PyInstaller, `Statistika.exe --self-test RESULT_FILE`, затем публикуется `Statistika-Windows-x64`. `workflow_dispatch` доступен из GitHub после появления workflow в ветке по умолчанию. EXE не коммитится. |

`catalog.json` в UTF-8: `{ "version": 1, "source": "имя.pdf", "points": { "35": "точный текст" }, "rules": { "35": ["характерная фраза"] } }`. Это пример структуры, не содержимого. Пользовательский файл заменяется атомарно; его можно копировать для настройки другого ПК. Не переносите правила с другой редакции PDF без проверки.

## Когда появятся файлы заказчика

1. Откройте PDF, проверьте извлечение всех нужных пунктов, особенно переносы по страницам, колонтитулы, скобки, примечания и исключения. Вручную сверьте номера и описания в редакторе. Для скана используйте внешнее OCR и проверьте распознавание. Если документ должен быть встроен в EXE, сохраните проверенный JSON в `statistika/data/catalog.json` и укажите фактический источник; распространение оригинального документа без необходимости не требуется.
2. Определите тип ведомости, лист и фактические заголовки. Сверьте пять полей на нескольких строках с источником, включая дробные значения, нули и конец периода. Уточните смысл «Расход», если это заголовок исходного файла; не принимайте все движения за продажи.
3. Согласуйте характерные фразы и исключения для каждой группы. Покройте тестами анонимизированные примеры совпадений, конфликтов, товаров вне перечня и ручного переназначения. Не храните персональные данные и реальные обороты в тестах.
4. Выполните `python -m pytest -q`, проверьте импорт, ручное переназначение и экспорт на Windows. После `push` проверьте соответствующий запуск Actions и наличие EXE в артефакте. Успешный smoke-тест EXE не подтверждает корректность группировки на ещё не предоставленных файлах.
